Agents, CI, and Workers

Why agents need their own command

Coding agents such as Claude Code and Codex run each command in a fresh shell. The cd hook never runs for them, so the secrets never load. noenv exec loads them for one command.

Run a command with noenv exec

~/code/api ❯ noenv exec -- npm run dev
noenv: loaded 12 secrets for github.com/acme/api (development)

For each command, noenv exec does these steps:

  1. It finds the repository from the current directory.
  2. It picks the account for that repository. See more than one team.
  3. It removes secrets that your shell loaded for a different repository, so values do not leak between projects.
  4. It loads the secrets and runs the command. It prints which project it loaded, never the values.

Outside a noenv project, it runs the command without secrets. If the server cannot be reached, it uses the last encrypted copy on your machine and says so.

Tell your agent

Add this line to CLAUDE.md or AGENTS.md in the repository:

Run commands that need environment variables with `noenv exec -- <command>`. Do not create .env files.

To let an agent save a secret without a prompt, pipe the value:

printf '%s' "$VALUE" | noenv secret set KEY

Scripts and CI

The same command works in scripts: noenv exec -- npx wrangler deploy. The machine needs a signed-in noenv session for the account.

Push secrets to a Worker

noenv wrangler copies secrets from noenv to your Cloudflare Worker with wrangler secret bulk. The values go to Wrangler on stdin, so they never show on screen or land in a file.

noenv wrangler                      # pick the secrets in a list
noenv wrangler STRIPE_KEY API_KEY   # push these, no list

In the list, move with the arrow keys or j and k. Press space to select, a to select all, enter to push, and esc to cancel.

~/code/api ❯ noenv wrangler
Push secrets from github.com/acme/api (production) to Wrangler
› [x] STRIPE_KEY
  [x] RESEND_API_KEY
  [ ] DATABASE_URL
2 of 3 selected · space select · a all · enter confirm · esc cancel

Push on every change

List the keys in .noenv. noenv pushes them after each noenv secret set and noenv secret rollback:

[wrangler]
secrets = ["STRIPE_KEY", "API_KEY"]
environment = "production"   # optional: the noenv environment to copy from
env = "staging"              # optional: passed to wrangler as --env

These keys start selected in the list. Without a terminal, for example in CI, noenv wrangler pushes this list. The CLI uses the wrangler in the repository's node_modules, or the one on your PATH.

Changes made in the dashboard do not push to Wrangler. Run noenv wrangler after them.
