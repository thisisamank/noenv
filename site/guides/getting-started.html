Before you start

  • A Cloudflare account. The free plan is enough to start.
  • Node.js 22 or newer on each developer machine.
  • macOS or Linux with zsh or bash.
  • A device that supports passkeys: Touch ID, Face ID, Windows Hello, or a security key.

1. Deploy noenv

Click Deploy to Cloudflare. Cloudflare copies the repository to your account and creates one Worker, one D1 database, and one KV namespace.

The form asks for these values:

VariableWhat to enter
ADMIN_EMAILYour email address. This person becomes the first admin.
SETUP_TOKENA random string of at least 16 characters that you make up. You type it with your email to create the admin passkey. Not needed when email is on.
EMAIL_FROMA sender address on a domain with Cloudflare Email Sending, to email invites. Otherwise keep none.

2. Create your admin passkey

Open https://<your-worker>.workers.dev/dashboard/ and sign up with the same email and your setup token. If email is on, the dashboard sends you a setup link instead.

With email on, only a person who can read ADMIN_EMAIL can claim the deployment. Without email, a person needs both ADMIN_EMAIL and SETUP_TOKEN.

3. Install the CLI

$ npm install -g @thisisamank/noenv-cli

4. Connect your shell

Add these lines to ~/.zshrc or ~/.bashrc. The dashboard shows them with your URL filled in.

export NOENV_URL="https://<your-worker>.workers.dev"
eval "$(noenv shell zsh)"   # or: noenv shell bash

5. Approve the terminal

Open a new terminal and cd into a git repository. Your browser opens once. Approve the terminal with your passkey.

6. Add a project

The git origin of the repository is the project, for example github.com/acme/backend.

~/code/backend ❯ noenv init
Created project github.com/acme/backend
Created environment development
Created .noenv for https://noenv.acme.com, commit it so teammates load this project
~/code/backend ❯ noenv secret set API_KEY
Value:
Saved API_KEY as version 1 in github.com/acme/backend (development)
noenv: loaded 1 secrets for github.com/acme/backend (development)

noenv secret set reads the value without echo, so it does not show on screen or in your shell history.

Commit the .noenv file. It names the deployment and the environment, so your teammates' shells load from the right deployment, and an access problem shows a message instead of silence.

version = 1
deployment = "https://noenv.acme.com"
environment = "development"

Check your setup

Run noenv status. It shows the deployment, your account, and the current project.

Everyday commands

CommandWhat it does
noenv statusShow the deployment, your account, and the current project
noenv secret set KEYSave a secret as a new version
noenv secret listList the secrets in this environment
noenv secret history KEYList the versions of a secret
noenv secret rollback KEY VERSIONRestore an older version
noenv migrateMove this repository's .env files into noenv
noenv exec -- CMDRun a command with this repository's secrets, without the shell hook
noenv wrangler [KEY…]Push secrets to your Worker
noenv grant EMAIL ROLEGive a person access to this project and share the key

Work with more than one team

Each noenv deployment is one team. To use several deployments on one laptop, add each one with noenv account add URL. Then noenv init asks which one a repository uses. See Multiple accounts.
