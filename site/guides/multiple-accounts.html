Multiple accounts

Use one laptop and one CLI with several noenv deployments, for example your company, a client, and your own projects.

When you need accounts

Each noenv deployment is one team on one Cloudflare account. You need named accounts when one laptop works with more than one deployment, for example:

  • your company's deployment for work repositories,
  • a client's deployment for their repositories,
  • your own deployment for personal projects.

With one deployment, you do not need accounts. NOENV_URL in your shell profile is enough.

1. Add each deployment

Add each deployment by its URL:

~ ❯ noenv account add https://noenv.acme.com
Saved account acme (https://noenv.acme.com) as the default
~ ❯ noenv account add https://secrets.globex.io
Saved account globex (https://secrets.globex.io)

The deployment reports its team name, and the CLI saves the account under it. So every teammate gets the same name, and nobody has to type one. Admins set the name with TEAM_NAME when they deploy. Without it, the name comes from the Worker's address, for example acme for noenv.acme.com.

To use your own name, put it after the URL: noenv account add https://noenv.me.dev personal. The first account you add becomes the default.

2. Sign in to each account

Sign in once per account. Your browser opens, and you approve with the passkey for that deployment:

noenv auth acme
noenv auth globex

You can also skip this step. When you enter a repository of an account you are not signed in to, the shell starts the sign-in for you.

3. Choose the account for each repository

Run noenv init in the repository. With one account, it uses that account. With more than one, it asks:

~/code/acme-backend ❯ noenv init
Which account should this repository use?
› acme      https://noenv.acme.com
  globex    https://secrets.globex.io
  personal  https://noenv.me.dev

It saves the deployment URL, not the account name, in the repository's .noenv file. Commit the file.

version = 1
deployment = "https://noenv.acme.com"
environment = "development"

Agents and scripts cannot answer the question. They pass the account: noenv init --account acme.

Teammates and account names

The URL is the same for everyone on the team, so the shell hook, noenv exec, and every other command look for the local account with that URL. One teammate can call it acme and another work. Both load the same secrets. noenv does not guess from the git origin.

When a teammate clones the repository before they add the deployment, noenv tells them the command:

noenv: this repository uses the deployment https://noenv.acme.com, add it with `noenv account add https://noenv.acme.com`
noenv never connects to a URL from .noenv on its own. A cloned repository cannot point your shell at a server you did not add.

In a repository whose .noenv names no deployment, noenv uses NOENV_ACCOUNT, then the default account, then NOENV_URL. A setup with one deployment keeps working without accounts.

Move between repositories

When you cd from a repository of one account to a repository of another, noenv unloads the first set of secrets and loads the second. Values from one team never stay in your shell when you work on another team's code.

~/code/acme-backend ❯ cd ../globex-api
noenv: loaded 8 secrets for gitlab.globex.io/globex/api (development)

Coding agents get the same behavior with noenv exec. See Agents, CI, and Workers.

Manage accounts

CommandWhat it does
noenv account listList each account, its URL, and if you are signed in. * marks the default.
noenv account default NAMEUse NAME in repositories whose .noenv names no deployment
noenv account remove NAMEForget an account. Its key stays on this machine, so adding it again keeps your access.
noenv statusShow which account the current repository uses
 
~ ❯ noenv account list
* personal  https://noenv.me.dev  signed in
  acme  https://noenv.acme.com  signed in
  globex  https://secrets.globex.io  signed out

Use another account for one shell

To use a different account for one terminal session, set NOENV_ACCOUNT:

export NOENV_ACCOUNT=globex

It applies only in repositories whose .noenv names no deployment, until you close the terminal or run unset NOENV_ACCOUNT. A deployment in .noenv always wins.

Where accounts are stored

The list of accounts is in ~/.config/noenv/accounts.json. Each deployment has its own folder next to it, with its own session and key. Signing out of one account does not affect the others.

The deployment in .noenv needs CLI 0.3.0 or newer. Team names need a deployment that runs the current Worker. Run npm install -g @thisisamank/noenv-cli to update.
