Where policies apply

Admins set policies in the dashboard under Policies, at three levels:

  1. Organization: all projects.
  2. Project: one repository.
  3. Environment: one environment of a project.

A policy set at a lower level replaces the same policy from the level above it.

.env policy

The CLI checks the repository for .env files each time it loads secrets. The mode decides what happens:

ModeWhat happens on a developer machine
warnThe shell shows a warning. Secrets load. This is the default.
blockSecrets do not load while a matching file exists.
migrateSecrets do not load until the developer runs noenv migrate and removes the file.
deleteThe CLI deletes each file whose values noenv already stores. A file with new names is kept and blocks loading until the developer runs noenv migrate, so a .env file on a branch cannot add team secrets.

Include and exclude patterns pick the files. The defaults are .env and .env.*, without .env.example, .env.sample, .env.template, and .env.*.example.

delete removes files on your team's machines. It deletes only regular files that match the patterns, inside a git repository that noenv knows. It never follows symbolic links, never deletes folders, and keeps any file it could not verify.

Other policies

PolicyLevelDefaultEffect
Minimum CLI versionOrganizationNoneOlder CLIs must update before they load secrets.
Session expiryOrganization168 hoursPeople approve their terminal again after this time.
Minimum role for environment accessAllreaderPeople below this role cannot load the environment.

Devices and compliance

Devices lists every signed-in terminal and browser. For each one you see the person, the device name, the CLI version, when it was last seen, and the .env status for each repository and environment.

Sign a device out from the same page. The person approves the terminal again on the next load.

The CLI reports compliance itself. It shows the state of honest machines. It is not proof against a person who controls their own device.
