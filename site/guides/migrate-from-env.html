Migrate from .env

Move the .env files of a repository into noenv, verify every value, and delete the files safely.

What noenv migrate does

  1. It finds the .env files in the repository.
  2. It encrypts each value on your machine and uploads it to the current environment.
  3. It reads every value back and compares it with the file.
  4. When all values match, it asks if it can delete the file.

By default it reads .env and .env.*. It skips .env.example, .env.sample, .env.template, and .env.*.example. Admins can change these patterns in the .env policy.

Migrate a repository

  1. Go to the repository: cd ~/code/api.
  2. If the repository has no project yet, run noenv init.
  3. Run noenv migrate.
  4. Read the result for each file. Type y to delete a file that noenv has stored.
~/code/api ❯ noenv migrate
.env: 12 values are stored in noenv
Delete .env? [y/N] y
.env: deleted
noenv: loaded 12 secrets for github.com/acme/api (development)

When noenv keeps a file

noenv never deletes a file that it could not fully store. It keeps the file in these cases:

OutputCauseWhat to do
kept, values differ from noenv for KEYYour team already set KEY to a different value. noenv does not overwrite it.Decide which value is correct. Set it with noenv secret set KEY, then run migrate again.
skipped, invalid names: …The file has names that are not valid variable names.Fix the names in the file, then run migrate again.
kept, could not verify the uploadA value did not read back the same.Run migrate again. Check your connection.
kept, the file changedThe file changed while migrate ran.Run migrate again.

Staging and production files

migrate uploads into the current environment. The default is development. To migrate a staging file, select staging first:

NOENV_ENVIRONMENT=staging noenv migrate

noenv init creates a .noenv file in the repository. Edit it to make the repository always use an environment, or to list the secrets it needs:

version = 1
environment = "staging"

[secrets]
required = ["DATABASE_URL", "STRIPE_KEY"]

The .noenv file holds no secret values, so you can commit it. When a required secret is missing, the shell prints missing required secrets: ….

Move the whole team

After you migrate, ask your teammates to delete their own copies. To make this a rule, set the .env policy to migrate or delete. See Policies and devices.
